# ADR-0009: Диалог сохранения для экспорта — `tauri-plugin-dialog`, вызов только из Rust

**Статус:** принято (Итерация 9).

## Контекст

Экспорт JSON/CSV и резервная копия БД (раздел 5 ТЗ: "экспорт по явному
запросу пользователя, резервное копирование") требуют, чтобы пользователь
выбрал, куда сохранить файл. Варианты:

1. Frontend показывает диалог (`@tauri-apps/plugin-dialog`) и передаёт
   путь в команду → команда пишет файл по пути из IPC.
2. Rust сам открывает диалог внутри команды и сам пишет файл.
3. Писать в фиксированную папку (`Documents/DevLog`) без диалога.

## Решение

Вариант 2: крейт `tauri-plugin-dialog` (v2), диалог вызывается в
`commands/data.rs::data_export` через `app.dialog().file().blocking_save_file()`.

- Frontend **не получает** capability `dialog:*` и не может передать
  команде произвольный путь для записи — NFR "команды валидируют
  аргументы", "минимальные capabilities". Путь существует только как
  результат системного диалога, который видел пользователь.
- Команда `async`: блокирующий диалог нельзя вызывать в главном потоке.
- Вариант 3 отвергнут: пользователь не контролирует, куда уходит файл с
  историей работы.

## Совместимость с `x86_64-pc-windows-msvc`

Плагин использует `rfd` → нативный Windows `IFileSaveDialog` через
`windows-sys`, без C-зависимостей. Проверено: `cargo clippy`,
`cargo test`, `npx tauri build --no-bundle` на этой машине, smoke-запуск
release-сборки. Транзитивно тянет `tauri-plugin-fs` как библиотеку; сам
fs-плагин не регистрируется и прав фронтенду не даёт.
