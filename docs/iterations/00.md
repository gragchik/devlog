# Итерация 0 (Tauri) — Исследование ограничений и каркас

> Переписано с нуля на Tauri взамен Electron-версии (см.
> `docs/iterations/electron-archive/00.md` для истории). Решение и
> контекст перехода — в начале `.claude/tasks/DEVLOG_CLAUDE_CODE_TZ.md`.

## Что сделано

- Tauri 2.12.1 + React 18 + TypeScript (strict) + Vite 6. Структура:
  `src-tauri/` (Rust-ядро), `src/` (frontend, два HTML-входа: main-window и
  overlay).
- Главное окно: закрытие (`X`) скрывает, а не завершает процесс
  (`on_window_event` + `prevent_close()`).
- Overlay-окно: frameless, `always_on_top`, `skip_taskbar`, создаётся
  скрытым при старте, позиционируется у правого верхнего края монитора под
  курсором, переключается глобальным хоткеем `Ctrl+Alt+W`
  (`tauri-plugin-global-shortcut`), скрывается по Escape/кнопке `✕` (через
  `getCurrentWindow().hide()` из frontend) и по тому же хоткею повторно.
- Трей: «Открыть» / «Показать overlay» / «Приостановить (заглушка)» /
  «Сегодня» / «Выход», с динамическим текстом пункта паузы через
  `MenuItem::set_text`.
- Single-instance (`tauri-plugin-single-instance`, первый плагин в билдере).
- Capabilities: `capabilities/default.json` (main), `capabilities/overlay.json`
  (overlay) — оба на `core:default`, разделены по `label`, чтобы в будущем
  ужесточать независимо (ТЗ: права только там, где реально нужны).
- Команда `get_app_info` (версия/платформа/заглушка tracking-статуса) —
  общая для main и overlay, демонстрирует паттерн для всех будущих команд.
- 4 unit-теста на Rust (`cargo test`) — чистая геометрия позиционирования
  overlay (`compute_overlay_bounds`/`find_monitor_at`), вынесенная из
  Tauri-API в тестируемые функции.
- ADR-0005 (build tooling — Tauri CLI + Vite + встроенный bundler,
  заменяет ADR-0001). `docs/architecture.md` переписан с нуля под Tauri.

### Критическая проверка Rust/MSVC toolchain

На машине пользователя исходно не было ни `rustc`/`cargo`, ни MSVC Build
Tools (`vswhere.exe` отсутствовал). Пользователь поставил оба компонента
самостоятельно. Проверено: `rustc --version` (1.99.0), и, что важнее,
**реальная линковка** — `cargo new` + `cargo build` + запуск полученного
`.exe` на простом "Hello, world!" (линковка — единственное, что
`rustc --version` не проверяет, а именно она чаще всего падает без MSVC
Build Tools).

### Сквозной smoke-test реального приложения

`npm run dev` (= `tauri dev`): первая чистая сборка — **5 минут 6 секунд**
(компилируется ~370 транзитивных крейтов Tauri-экосистемы; инкрементальные
пересборки при правке Rust-кода — ~13 секунд благодаря встроенному
file-watcher в Tauri CLI). После сборки:

- Главное окно `DevLog` открывается автоматически — подтверждено:
  `Get-Process devlog | Select MainWindowTitle` → `DevLog`.
- Глобальный хоткей `Ctrl+Alt+W` открывает/закрывает overlay — подтверждено
  программно через Win32 `EnumWindows`/`IsWindowVisible`: 3 последовательных
  нажатия (с задержкой) дали ожидаемое чередование `false → true → false →
  true`, с временным логированием (`eprintln!`) в `toggle_overlay`,
  убранным после подтверждения.
- Как и в Electron-версии, одиночные "мгновенные" `SendKeys`-нажатия без
  задержки иногда не доставлялись (ограничение автоматизации в этой
  безголовой сессии, не баг приложения — см.
  `docs/iterations/electron-archive/00.md` и memory `devlog-env-quirks`) —
  с задержкой ~800мс между нажатиями результат стабилен и воспроизводим.
- Нет паник/ошибок в выводе `tauri dev` при старте, работе и остановке.

### Не подтверждено автоматически (нужна ваша ручная проверка)

Escape-закрытие overlay (клавиша, а не хоткей) и визуальная проверка
отсутствия security-warnings в DevTools — по тем же причинам, что и в
Electron-версии (среда автоматизации не держит настоящий foreground для
обычных клавиш). Чек-лист ниже.

## Проблемы окружения, с которыми столкнулись (и как решены)

1. **PATH Bash-сессии стал Windows-стиля (`;`-разделитель) после установки
   Rust/MSVC Build Tools**, из-за чего перестали резолвиться даже базовые
   команды (`which`, `ls`, `tail`), не говоря про `cargo`. Причина —
   двоеточие после буквы диска (`C:\...`) ломает парсинг `:`-разделённого
   Unix PATH. Решено явным заданием PATH в начале каждой bash-команды
   (сохранено в memory `devlog-env-quirks` для будущих сессий).
2. **`tauri::image::Image::from_bytes` не находился** — метод существует,
   но скрыт за `#[cfg(feature = "image-png")]`. Решено добавлением фичи
   `image-png` к зависимости `tauri` в `Cargo.toml`.
3. **`tauri::generate_handler![commands::get_app_info]` не компилировался**
   ("cannot find `__cmd__get_app_info`") — макрос `#[tauri::command]`
   генерирует скрытые элементы в модуле, где функция объявлена; `pub use`
   re-export их не переносит. Решено прямой ссылкой
   `commands::app_info::get_app_info` вместо реэкспорта.
4. **`npx tauri icon` сгенерировал iOS/Android/Windows-Store ассеты**,
   которые не нужны Windows-desktop MVP — удалены вручную после генерации.

## Чек-лист для ручной проверки

1. `npm run dev` → главное окно открывается, иконка в трее появляется
   (синий квадрат-placeholder, не финальный дизайн).
2. Открыть WebStorm, нажать `Ctrl+Alt+W` → overlay появляется поверх него
   у правого верхнего края экрана.
3. Нажать `Escape` → overlay скрывается.
4. Снова `Ctrl+Alt+W` → overlay открывается заново быстро (без задержки на
   пересоздание окна — в логах `tauri dev` не должно быть повторной
   компиляции/перезапуска процесса).
5. Нажать `✕` в overlay → скрывается.
6. В трее: «Показать overlay» → overlay открывается тем же способом.
7. В трее: «Приостановить (заглушка)» → текст пункта меняется на
   «Продолжить (заглушка)» (проверка механики меню, не реального
   трекинга — его ещё нет).
8. Закрыть главное окно через `X` → приложение остаётся в трее; «Открыть»
   в трее возвращает окно.
9. В трее «Выход» → приложение полностью завершается (`devlog.exe`
   исчезает из Диспетчера задач).
10. **Опционально, если есть второй монитор/нестандартный DPI:** повторить
    шаги 2–3 там — учтите известное ограничение (см. "Что сознательно НЕ
    сделано" в `docs/architecture.md`): overlay использует полные границы
    монитора, не workArea, поэтому может на несколько пикселей перекрыть
    taskbar — это ожидаемо для Итерации 0, точная версия в Итерации 6.
11. Открыть DevTools (`Ctrl+Shift+I` в фокусе окна) и убедиться, что в
    консоли нет ошибок/warning при вызове `get_app_info`.

## Оставшиеся риски

1. **`rusqlite` не проверен** — план на Итерацию 1 (ожидаемо проще, чем
   было с `better-sqlite3`/Electron — нет проблемы ABI нативных Node-модулей,
   т.к. Rust-зависимости компилируются прямо в бинарник, но нужно
   подтвердить на практике).
2. **Win32 foreground-detector (крейт `windows`) не реализован** — план на
   Итерацию 2.
3. **Overlay warm-open p95 не замерено инструментально** — субъективно
   быстро (~13 сек пересборка при dev, не показатель; в release-сборке
   открытие не требует пересборки вообще) — точный замер, когда будет что
   измерять помимо пустой заглушки (Итерация 6).
4. **Workarea-aware позиционирование** — см. выше, известное отступление.
5. **Первая чистая Rust-сборка — 5+ минут** — не блокер, но стоит знать
   (на CI/чистой машине будет так же).
6. **Трей-иконка — placeholder**, не финальный дизайн — замена перед
   релизом (Итерация 10).
