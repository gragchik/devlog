# Итерация 3 (Tauri) — Git context и связывание с Jira key

## Что сделано

- `tracking::git_adapter` — `git -C <repo> branch --show-current` через
  `std::process::Command`, с явной обработкой detached HEAD (пустой
  stdout — документированное поведение git, не ошибка), отсутствия git
  в PATH, "not a git repository". Плюс `head_mtime()` — mtime `.git/HEAD`
  как недорогая эвристика активности репозитория.
- `tracking::issue_key::extract_issue_key()` — нормализация (подчёркивания
  → дефисы, uppercase) + настраиваемый regex на проект (FR-03.3).
- `tracking::git_context::resolve()` — чистая функция приоритета FR-03.4:
  явный pin (зарезервирован для Итерации 6) → активный репозиторий+ветка →
  `preferences.defaultIssueKey` проекта → «Нераспределено».
  `pick_most_recently_active()` — выбор среди нескольких настроенных
  репозиториев по дате изменения `.git/HEAD`.
- `tracker.rs`: git-контекст резолвится при `state == Tracking`, сливается
  с состоянием через `weaker_confidence` (итоговая confidence — минимум из
  двух, не одна произвольная).
- 15 новых тестов (issue_key: 5, git_context: 9, tracker::weaker_confidence: 1).

### Сквозная проверка на реальных данных (не только unit-тестами)

Временно добавлен `project`, указывающий на сам репозиторий DevLog
(`D:/soft/worklog`), приложение запущено через `npm run dev`:

```
# на branch=master (реальная ветка репозитория в момент теста)
state=TRACKING cat=ide proc=webstorm64.exe project=selftest branch=master issue=None
  | ...; branch 'master' has no issue key and no default rule — unassigned

# создана тестовая ветка feature/TEST-123-verify-tracker (git checkout -b)
state=TRACKING cat=ide proc=webstorm64.exe project=selftest branch=feature/TEST-123-verify-tracker issue=TEST-123
  | ...; branch 'feature/TEST-123-verify-tracker' matched issue regex
```

Переход между этими двумя состояниями произошёл **ровно на границе**
переключения ветки (между двумя последовательными poll) — именно та
дискретность данных, которая нужна Session Engine (Итерация 4) для
корректного разбиения сессий. Тестовая ветка удалена сразу после проверки
(`git checkout master && git branch -D feature/TEST-123-verify-tracker`),
никаких следов в истории репозитория не осталось.

## Оставшиеся риски / сознательно отложено

1. **"Активный репозиторий" при нескольких настроенных — эвристика по
   mtime `.git/HEAD`**, не точное знание, какой проект открыт в IDE (нет
   чтения заголовков окон — принципиальное ограничение приватности, ТЗ
   FR-02.4). При одновременной работе с несколькими репозиториями без
   явных коммитов/переключений веток в части из них точность может
   снижаться. Точное решение — JetBrains IDE plugin, Итерация 11
   (опционально, после MVP).
2. **Explicit pin (ручное закрепление задачи в overlay)** — параметр уже
   есть в `git_context::resolve()`, но ни один вызывающий код пока не
   передаёт в него значение — появится вместе с overlay-редактированием
   (Итерация 6).
3. **GitLab API/коммиты/MR/code review** — не входит в MVP (ТЗ FR-03.6),
   опциональное расширение Итерации 11+.
4. **`preferences.defaultIssueKey`** реализован на уровне данных и
   покрыт тестом, но нет UI для его настройки — Итерация 5 (Settings).
