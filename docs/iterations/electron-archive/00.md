# Итерация 0 — Исследование ограничений и каркас (Electron, архив)

## Что сделано

- Electron + React + TypeScript (strict) + Vite через `electron-vite`
  (ADR-0001).
- Три build-таргета: main (`src/main/index.ts`), два preload
  (`main-preload.ts`, `overlay-preload.ts`), два renderer-входа
  (`main-window`, `overlay`).
- Главное окно: закрытие (`X`) скрывает, а не завершает процесс; показывает
  версию/платформу/заглушку tracking-статуса через типизированный IPC.
- Overlay-окно: frameless, `alwaysOnTop`, `skipTaskbar`, позиционируется у
  правого верхнего края дисплея, ближайшего к курсору, в границах
  `workArea`; переключается глобальным хоткеем `Ctrl+Alt+W`, закрывается по
  Escape (обработка и в main через `before-input-event`, и в renderer) и по
  кнопке `✕`.
- Трей: пункты «Открыть», «Показать overlay», «Приостановить/Продолжить»
  (заглушка — реального трекера ещё нет), «Сегодня» (пока просто открывает
  главное окно), «Выход».
- Single-instance lock (`requestSingleInstanceLock`).
- Security-периметр: `contextIsolation: true`, `nodeIntegration: false`,
  `sandbox: true` на обоих окнах; whitelisted IPC с проверкой
  `senderFrame`; CSP (заголовок + meta-тег); блокировка навигации/popup'ов
  вовне.
- Типизированный shared-слой: `IPC_CHANNELS`, `AppInfo`/`MainWindowApi`/
  `OverlayApi`, `TrackingStatus` (заглушка), `secondsToHms` (чистая функция,
  6 unit-тестов).
- 4 ADR (`docs/decisions/0001`–`0004`): build-tooling, SQLite-драйвер
  (план), Win32 foreground-detector (план), Jira-провайдер (план).
- `docs/architecture.md` — описание процессов/окон/IPC/security-периметра и
  явный список того, что сознательно не реализовано.

### Ручной smoke-test (выполнен в этой сессии через Win32-автоматизацию, не через обычный клик мышью)

- `npm run dev` поднимает Vite dev-server и Electron без ошибок и падений
  (после установки бинарника Electron — см. "Проблемы" ниже).
- Главное окно открывается автоматически при старте (подтверждено:
  `MainWindowTitle == 'DevLog'` у процесса main).
- Глобальный хоткей `Ctrl+Alt+W` открывает overlay — подтверждено
  программно: после отправки комбинации через `SendInput`
  (`System.Windows.Forms.SendKeys`) окно `DevLog Overlay` стало
  `IsWindowVisible() == true`.
- **Не подтверждено автоматически:** закрытие overlay по `Escape`. В этой
  среде выполнения `GetForegroundWindow()` возвращал `0` (нет настоящего
  foreground-окна в сессии), и `SendKeys` периодически падал с `Access is
  denied` — то есть обычная (не глобальная) клавиша физически не
  гарантированно доставлялась в фокус overlay. Глобальный hotkey сработал,
  потому что `RegisterHotKey` в Windows доставляется через `WM_HOTKEY`
  независимо от фокуса — а Escape зависит от обычной доставки input
  конкретному окну, что в headless/без-foreground сессии ненадёжно. Это
  ограничение среды автоматизации, а не диагностированный баг — но это
  **не равноценно** ручной проверке мышью/клавиатурой на обычном рабочем
  месте. Код реализует Escape-закрытие в двух местах (main
  `before-input-event` + renderer `keydown`), но финальная проверка —
  ваша (чек-лист ниже).

## Известные проблемы, с которыми столкнулись (и как решены)

1. **`which node` / `node: command not found` в Bash после перезагрузки
   Windows.** Причина — устаревший хеш команд в сессии bash (nvm обновил
   активную версию Node во время/после ребута). Решено `hash -r`.
2. **`npm install` падал с ERESOLVE**: `electron-vite@2.3.0` поддерживает
   только `vite@^4||^5`, а по умолчанию поставился `vite@6`. Решено
   обновлением `electron-vite` до `^5.0.0` (поддерживает `vite@^5||^6||^7`).
3. **`electron-vite dev` падал с `Error: Electron uninstall`.** Postinstall
   `electron` пакета (скачивание бинарника ~245MB с GitHub releases) не
   успел/не отработал при обычном `npm install`. Решено повторным ручным
   запуском `node node_modules/electron/install.js` — на этот раз скачалось
   и распаковалось успешно. **Риск:** на машине пользователя та же заминка
   может повториться при первом `npm install` — если `npm run dev` сразу
   упадёт с этой ошибкой, подождать и повторить команду.
4. **`npm audit` исходно показывал 5 уязвимостей** (3 moderate, 1 high, 1
   critical) — все транзитивные, dev-only, через `vitest@2.1.9` → свой
   внутренний `vite-node` → старый `vite@5.4.21`/`esbuild` (уязвимость
   класса "dev-server CORS", неприменима к production/packaged коду).
   Решено обновлением `vitest` до `^4.1.11`.

## Чек-лист для ручной проверки (у вас, на обычной Windows-сессии)

1. `npm run dev` → главное окно открывается, трей-иконка появляется (синий
   квадрат-placeholder — не финальный дизайн, см. `scripts/gen-placeholder-icons.mjs`).
2. Открыть WebStorm (или любое другое окно), нажать `Ctrl+Alt+W` → overlay
   появляется поверх него у правого верхнего края экрана.
3. Нажать `Escape` → overlay скрывается.
4. Снова `Ctrl+Alt+W` → overlay открывается заново быстро (без задержки на
   пересоздание окна).
5. Нажать `✕` в overlay → скрывается.
6. В трее: «Показать overlay» → overlay открывается тем же способом.
7. В трее: «Приостановить (заглушка)» → пункт меняется на «Продолжить
   (заглушка)» (это проверка механики меню, не реального трекинга — его
   ещё нет).
8. Закрыть главное окно через `X` → приложение остаётся в трее (не
   завершается), «Открыть» в трее возвращает окно.
9. В трее «Выход» → приложение полностью завершается (все процессы
   electron.exe исчезают из Task Manager).
10. **Опционально, если есть второй монитор/нестандартный DPI:** повторить
    шаги 2–3 на втором дисплее и при масштабировании 125–150% — проверить,
    что overlay целиком виден и не съезжает за край экрана. (Это из
    тест-кейсов FR-06, системно будет закрыто в Итерации 6 — сейчас просто
    любопытно, не ломается ли базовое позиционирование уже сейчас.)
11. Откройте DevTools overlay/main окна (`Ctrl+Shift+I` при показанном
    фокусе на окне — если недоступно, временно добавить `win.webContents.openDevTools()`
    в код) и убедитесь, что в консоли нет Electron security warnings
    (`Electron Security Warning (...)`).

## Оставшиеся риски

1. **SQLite-драйвер (`better-sqlite3`) не проверен** — ADR-0002, план на
   Итерацию 1.
2. **Win32 foreground-detector (`koffi`) не реализован и не проверен** —
   ADR-0003, план на Итерацию 2. Без него Activity Tracker не может читать
   чужое foreground-окно.
3. **Overlay warm-open p95 ~500мс не замерено инструментально** — нужен
   реальный профайлинг на итерации 6, когда появится что измерять помимо
   пустой заглушки.
4. **Позиция overlay не сохраняется между запусками** (FR-06.4) — сейчас
   всегда у правого верхнего края ближайшего к курсору дисплея.
5. **Нет UI переназначения hotkey при конфликте** — только
   `Notification`. Если `Ctrl+Alt+W` занят другим вашим приложением,
   увидите уведомление, но сменить комбинацию через UI нельзя до Итерации 6.
6. **Первый `npm install` может потребовать повторного запуска** из-за
   проблемы №3 выше (скачивание бинарника Electron) — не специфично для
   кода проекта, но стоит знать на вашей машине.
7. **Трей-иконка — placeholder** (сплошной синий квадрат,
   программно сгенерированный PNG), не финальный дизайн — замена перед
   релизом, Итерация 10.
