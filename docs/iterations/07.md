# Итерация 7 (Tauri) — Jira Integration + Worklog Review

Начата 2026-10-02 (слой данных и HTTP-клиент, WIP-коммит `5a363f8`),
завершена 2026-10-04.

## Что сделано

**Backend**

- `integrations/jira/jira_cloud.rs` — доработан клиент Jira Cloud REST v3:
  - `adjustEstimate=leave` на каждом POST worklog (FR-07.8 — раньше не
    передавался, и Jira по умолчанию уменьшала remaining estimate);
  - таймаут 30 с (зависший запрос = `NetworkUnknown`, не вечное ожидание);
  - редиректы не исполняются, HTML вместо JSON — ошибка: SSO/VPN-портал
    не может выглядеть как успешное соединение (FR-07.10);
  - `verify_connection` возвращает пользователя (`accountId`,
    `displayName`); новые `get_issue` и `list_worklogs_near`;
  - `search_issues` удалён: использовал `/rest/api/3/search`, который
    Atlassian уже вывел из эксплуатации, и нигде не вызывался.
- `domain::jira::JiraError` — понятные тексты для 3xx/401/403/404/429/5xx,
  обрезка длинного тела ответа; `JiraConnectionInput` — `Debug` без токена.
- `worklog/drafts.rs` — черновики из сессий дня (FR-08.1).
- `worklog/submission.rs` — протокол отправки: локальная + remote проверка
  дублей, `pending` до запроса, `posted/failed/unknown`, reconciliation,
  ручное разрешение (подробно — `docs/architecture.md`).
- `jira_submissions::mark_stale_pending_as_unknown` — вызывается при старте.
- `commands/jira.rs` — 13 команд, все только для главного окна.
- `tracking::issue_key::is_valid_issue_key` — строгий формат ключа перед
  подстановкой в URL.
- `show_main_window_command(tab)` — "Отчёт" в overlay открывает Worklog
  (закрыт риск №3 из Итерации 6).
- Сняты все временные `#[allow(dead_code)]` с Jira-модулей.
- ADR-0008: токен — `keyring` / Windows Credential Manager.

**Frontend**

- Вкладка **Worklog**: дата (вчера по умолчанию) → "Сформировать из
  сессий" → правка задачи/минут/комментария → выбор → **preview** (задача,
  дата и начало, время, текст, итог, "estimate не меняется") → "Отправить
  N в Jira" → результат по каждой записи. Статусы: черновик / в Jira (#id)
  / ошибка / результат неизвестен (+ "Проверить в Jira", "Запись есть",
  "Записи нет"). Баннер неразрешённых отправок за другие дни.
  "Копировать отчёт" — fallback без Jira.
- Settings → **Jira**: адрес, email, токен (password-поле, после
  сохранения очищается), "Сохранить и проверить", "Проверить",
  "Отключить".

## Acceptance checklist (раздел 8 ТЗ, "Готово, когда")

- [x] Пользователь может проверить и отправить несколько записей —
  выбор + preview + `submit_drafts` по списку
  (`successful_post_marks_draft_submitted_with_remote_id`).
- [x] Network failure не теряет draft —
  `offline_jira_blocks_everything_without_touching_drafts`,
  `timeout_leaves_unknown_and_never_reposts_blindly`.
- [x] Timeout не вызывает дубли без проверки — `unknown` блокирует повтор,
  reconciliation находит принятую запись
  (`reconcile_finds_worklog_accepted_before_timeout`) или разрешает
  повтор, если её нет (`reconcile_without_remote_worklog_allows_resubmit`);
  упавший посреди POST процесс → `unknown` при старте.
- [x] Remote-дубли: свой worklog на то же время блокирует POST, чужой — нет.
- [x] Копирование отчёта как fallback.
- [x] Estimate не меняется неожиданно — `adjustEstimate=leave`
  (`post_worklog_always_leaves_estimate_untouched`).
- [x] E2E-сценарий 8 (remote id и `posted` сохраняются в БД).
- [~] E2E-сценарий 7 на реальной Jira (401/timeout) — автоматизирован
  на моках; на настоящей Jira — ручной чек-лист ниже.

## Чек-лист для ручной проверки (нужна ваша Jira Cloud)

1. id.atlassian.com → Security → API tokens → создать токен.
2. Settings → Jira: `https://<company>.atlassian.net`, email, токен →
   "Сохранить и проверить" → должно показать ваше имя. В "Диспетчере
   учётных данных Windows" появится запись `DevLog`.
3. Неверный токен → "Jira 401: неверный email или API token".
4. Без VPN (если Jira за VPN/SSO) → понятная ошибка про VPN/SSO, не "успех".
5. Timeline: назначить вчерашним сессиям реальную тестовую задачу.
   Worklog → Вчера → "Сформировать из сессий" → поправить минуты/текст →
   отметить → "Предпросмотр" → "Отправить". В Jira у задачи появится
   worklog, remaining estimate не изменится.
6. Повторно отправить тот же черновик нельзя (чекбокс неактивен).
7. Перезапустить DevLog — статус "В Jira (#id)" сохранился.
8. Отключить сеть посреди отправки (или выдернуть кабель сразу после
   нажатия) → статус "Результат отправки неизвестен"; после возврата сети
   "Проверить в Jira" сам найдёт запись или разрешит повтор.
9. Overlay → "Отчёт" → главное окно открывается на вкладке Worklog.

## Оставшиеся риски / сознательно отложено

1. **Data Center/Server** не реализован (ADR-0004 — по запросу; целевая
   Jira — Cloud).
2. **Редактирование опубликованных worklog'ов** (FR-07.9) — после первой
   стабильной версии; сейчас отправленный черновик read-only.
3. **Черновики не пересчитываются** при последующей правке сессий —
   чтобы не затирать ручные правки. Пересчёт = удалить черновик и
   сформировать заново. Итерация 8 может добавить явное "Пересчитать".
4. **Remote-сверка ищет совпадение по автору + `started` (±60 с) +
   времени.** Если пользователь сам вручную завёл в Jira такую же запись,
   DevLog посчитает её дублем и не отправит — это безопасная сторона.
5. **Jira за SSO без API-доступа** — токен не поможет, только понятная
   ошибка (FR-07.10: не обходить политику безопасности компании).
